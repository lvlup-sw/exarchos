03System diagnosis

Five structural gaps explain the trace

Existing provenance was not captured at the failure boundary

Package version, build SHA, plugin version, and generated-skill hash should already identify the running artifact. The dogfood preflight must record and compare them before attributing behavior to current source.

Gate scope, owner, and cadence are conflated

The old loop lets an implementer run focused tests, the task runbook rerun adequacy/static/integration, the lead rerun targeted tests after merge, and review run combined checks. The recent durable producer and runner census are the right direction; closure means every enforceable gate flows through them and no direct emitter or shell path remains.

Hand-rolled contracts remain editable in parallel

Interfaces, Zod schemas, registry metadata, runbooks, CLI rendering, skills, runtime YAML, and examples can all describe the same behavior. A stale generated skill can preserve a defect after source code has moved on.

Local closure is strong; global closure is weak

Registries prove providers exist and actions have schemas, but no single graph proves public action → dispatch → handler → owned effect → output contract → packaged fixture for every capability.

Temporary and advisory controls lack structural exits

Compatibility parsers, manual fallbacks, advisory checks, and swallowed effects can persist indefinitely unless each has an owner, CI disposition, and measurable promotion or removal condition.

05Options

Three plausible paths

Only one balances immediate relief with recurrence prevention.

A

Patch train

Open one issue for each report item and fix them in severity order.

  • Fast visible closure
  • Small review surfaces
  • Preserves duplicated contracts
  • Does not explain source/runtime mismatches
Use only for containment.
B

Phase-gate closure only

Generate and centralize phase-gate contracts without auditing the wider shipped surface.

  • Better than isolated patches
  • Completes current evidence work
  • Leaves the same drift classes elsewhere
  • Adds another targeted closure island
Still too narrow.
C

Structural closure audit

Delta-audit the latest branch and build one convergence plan for contracts, effects, packaging, and proof.

  • Addresses defect classes, not instances
  • Reuses existing registries and runner census
  • Makes drift and reachability graph failures
  • Gives every patch a retirement condition
Recommended.
06Program

Six tracks, sequenced by structural dependency

T0

Delta structural audit

Re-score the seven principles on the latest branch. Verify what the canonical gate runner, durable producer, evidence migrations, and ownership census closed after the July 21 assessment.

T1

Generated shared boundaries

Use Strategos.Contracts TypeSpec + WorkflowDefinitionV1 for workflow semantics and one richer Exarchos action API contract for dispatch semantics. Project standard MCP 2026-07-28 schemas, CLI, docs/skills, fixtures, and graph metadata from that contract.

T2

Ship-surface graph

Generate authored workflow → IR → compiled topology/policy → public action → handler → owned effect → output → packaged fixture. Missing or alternate edges fail one closure check.

T3

Close proof-producing effects

Route every enforceable gate through the canonical runner, persist evidence before success, reject direct emitters, and let admission consume pass/fail/skipped/indeterminate explicitly.

T4

Driftable artifact inventory

Model binaries, plugin caches, generated skills/agents/hooks, runtime embeddings, command aliases, examples, and user installs as revision-bound artifacts with existing provenance/hash checks.

T5

Ratchet temporary controls

Require every advisory, compatibility path, containment patch, and manual fallback to declare an owner, CI disposition, and measurable promotion or removal condition.

Gate ownership: from repeated commands to one evidence chain

ProduceOne provider runs the check against a subject digest and records toolchain identity.
PersistThe canonical runner writes subject-bound evidence before returning success.
ConsumeTask, wave, or review admission selects valid evidence by subject and policy, not by rerunning folklore.
InvalidateA changed commit, diff, policy, producer, or toolchain digest makes prior evidence ineligible.
07IR convergence

v2.12 proves; v3.0 consolidates

The system design names #1258 as the consolidation endpoint. Every interim mechanism must lower into workflow IR, remain at an explicit runtime chokepoint, or be deleted.

v2.12 / additive proof substrate
  • Characterize legacy transition decisions and bypasses.
  • Persist subject-bound evidence through the canonical runner.
  • Record phase-attempt identity, provenance, supersession, contradiction, and reliability.
  • Run audit/shadow evaluation without changing legal behavior.
  • Do not freeze a temporary public admission contract.
v3.0 / shared IR cutover
  • Extend Strategos.Contracts TypeSpec and generate Exarchos Zod.
  • Compile closed edge conditions, gate declarations, and admission policies from WorkflowDefinitionV1.
  • Generate MCP and CLI presentation from the Exarchos action API contract.
  • Migrate built-in workflows through #1258.
  • Enable admission and delete legacy guards, HSM definitions, and closed-form playbooks.

MCP is the wire projection, not the whole Exarchos API contract.

Do we extend MCP?

  • No protocol fork. External clients receive standard MCP input/output schemas, structured content, and standard annotations.
  • The generated internal action contract also carries trusted phases/roles, gate and auto-emission metadata, dispatch/economy hints, long-running posture, deprecation, capability posture, and effect ownership.
  • That richer contract generates the dispatch interfaces, MCP registration, CLI/help, docs/skills, ship-graph nodes, and conformance fixtures.
  • Exarchos-specific metadata stays in the generated internal module or companion manifest; clients that do not know it still see valid MCP tools.

08Sequence

Audit first, then converge

Phase A / Delta

Refresh the structural assessment

Assess the latest feature branch, record closed gaps, and emit machine-readable contract, effect, artifact, advisory, and packaged-proof inventories.

Phase B / Generate

Collapse the shared boundaries

Generate workflow semantics from Strategos.Contracts/WorkflowDefinitionV1 and dispatch semantics from the Exarchos action API contract, with MCP/CLI/docs as projections; prove every derivative cannot drift independently.

Phase C / Close

Build graph closure

Connect registries into the ship-surface graph, eliminate unowned effect paths, and require packaged fixtures for every shipped capability.

Phase D / Ratchet

Retire temporary controls

Promote or remove advisories by exit condition, bind dogfood to artifact provenance, and convert every accepted incident into an unfiltered structural check.

09Exit criteria

Define success before the rerun

A green merge is insufficient. The next dogfood must prove the governance system itself is trustworthy.

Dogfood preflight records and matches package version, build SHA, plugin version, and generated-skill hash.
A four-task wave in a 17-task workflow reports exactly four expected worktrees.
Two real processes append concurrently without event/HWM divergence.
Restart preserves stream appendability and projection consistency.
Test adequacy discovers committed test diffs and handles new source paths.
The full integration suite runs once per wave from a structured report.
No task is complete before every task-scoped blocker passes.
The canonical unified spec passes without compatibility headings.
Plan-time coverage accepts future tests while validating declarations.
Risk-tier behavior is verified against the current packaged artifact before new policy is proposed.
Repeated infrastructure failures emit friction and reduced-mode guidance.
Events, projections, and git reconstruct the same trace without arbitration.
Every public action has one reachable implementation, owned effect, output contract, and packaged fixture.
Every advisory or temporary compatibility path has an explicit exit condition.
Every v2.12 mechanism names its v3.0 IR lowering, non-IR chokepoint, or deletion milestone.
The shadow corpus meets the quantitative cutover gate before legacy admission is replaced.
A baseline-vs-candidate benchmark artifact records raw samples, provenance, variance, and regression budget.
